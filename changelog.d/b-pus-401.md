### Bug fixes

- Paperless-ngx 3 no longer computes and sends the IDs of every matching document with each page of each search, the newest documents of the dashboard and each check: once Paperless names version 10 of its API, as every 3.x does, the app asks for that version instead of version 9, in which Paperless adds that list to every answer. For a common word in a large archive, the list was far longer than the 25 hits that the search asked for, and the web search asks while you type. Paperless-ngx 2 is still asked for version 9. `occ paperless_unified_search:check` reads the IDs that it compares with the files from the pages of the documents then.
- A Paperless that refuses version 10 of its API after it named it, as a Paperless newer than the app may one day, now says that Paperless Unified Search needs an update, instead of telling you that Paperless is older than 2.16. When Paperless refuses one version, **Test connection and save** and `occ paperless_unified_search:test` ask once for the other, so a Paperless that was updated or restored from an older backup connects again; the set-up of the search account does the same.
- The background job of the notifications about new documents no longer writes into the configuration of the apps every five minutes when nothing changed, which emptied Nextcloud's cache of that configuration for all apps each time, also on a server where nobody asks for notifications: a run without news writes nothing, the moment of the last answer of Paperless alone is stored at most once an hour, and a pause deletes the progress of the job only where one is stored.
